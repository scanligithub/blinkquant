# BlinkQuant IA v2 — IA5 产品对象与成果管理闭环

状态：盘点与验收基线

## 目标

验证 IA v2 的核心对象在创建、编辑、运行、保存、刷新、跨页面跳转中的完整性；优先补齐测试，不重复实现已经存在的能力。

## 对象与关系

- 用户 → 多个自选股列表 → 股票代码；列表及其成员必须按当前登录用户隔离。
- 用户 → 选股策略 → 不可变版本快照；策略可用于选股，也可作为回测策略的来源。
- 回测策略 → 版本快照；回测运行应保存足以重现本次运行的配置快照。
- 选股任务/回测任务 → 成果库条目；历史成果应保留任务完成时的输入、策略引用/快照与结果，不应随当前策略修改而漂移。
- 成果详情 → 任务详情、股票详情或自选股列表的导航应使用稳定的真实 ID。

## 验收分段

### IA5.0 — 基线与低风险路由兼容
- 固化对象关系、用户隔离和历史快照的验收边界。
- 将旧路径 `/watchlist` 重定向到正式路径 `/watchlists`；正式导航继续只使用复数路径。
- 不更改数据库 schema、Scheduler、任务 API 或计算引擎。

### IA5.1 — 策略库
- 选股策略创建、编辑、版本历史、删除与来源关系。
- 回测策略保存、编辑、版本历史，以及从回测策略提取选股策略。
- 来源策略 ID 和版本必须属于当前用户；客户端提供的 user ID 不可信。

### IA5.2 — 选股成果
- 成果库分页/类型筛选、重命名、删除、快照和股票代码列表。
- 成果应与完成任务关联；删除成果不应误删原始任务。
- 将选股结果批量加入指定自选股列表时应按用户所有权校验。

### IA5.3 — 回测成果
- 回测任务、策略配置快照、交易/绩效结果和成果详情保持关联。
- 编辑或删除当前策略不能改变已完成历史成果所显示的运行快照。

### IA5.4 — 自选股
- 一个用户可有多个列表；创建、重命名、删除、增删股票和刷新持久化。
- 不能读取或修改其他用户的列表/成员；默认列表保护行为明确。

### IA5.5 — 端到端与生产验收
- 从策略 → 运行 → 成果 → 股票/自选股或任务详情的跨页面链路。
- 用两个账号验证数据隔离；在生产环境只执行可控的小型操作并清理测试数据。
- 验收后记录真实 CI 与生产证据；静态检查或 HTTP 200 不等于端到端通过。

## 本轮边界

本轮先实施 IA5.0 的 `/watchlist` 兼容重定向，并把回归断言加入现有 Frontend CI。其余子阶段先基于现有 API/组件盘点，按小步 PR 推进。
