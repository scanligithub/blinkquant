# BlinkQuant IA v2：产品信息架构与页面树

状态：设计基线（先定 IA，不在本阶段重写页面）
适用项目：`scanligithub/blinkquant`
前端：Next.js App Router，`frontend/src/app`

## 1. 设计目标

- 登录后的默认工作区仍是选股；选股是产品核心工作流。
- 将选股、股票研究、自选股、策略、任务、成果和系统运行状态按业务职责分开。
- 任务表示一次执行；成果是不可被当前策略/自选股修改反向改变的历史快照。
- 先拆页面和职责，再迁移状态与 API；不一次性重写约 1200 行的 `page.tsx`。
- 现有 API 与计算内核尽量保持不变，页面重构不改变调度语义：选股优先，任务中心只负责展示/管理任务，不直接承担调度职责。

## 2. 一级导航

| 一级导航 | 默认页面 | 页面职责 |
|---|---|---|
| 选股 | `/select` | 编辑/选择选股策略、设置日期与周期、提交选股任务、查看本次结果摘要 |
| 股票研究 | `/stocks` | 搜索股票、查看 K 线/指标/基本信息；从结果或自选股进入具体股票 |
| 自选股 | `/watchlists` | 管理多个用户自选股列表及其股票成员；可将列表作为回测股票池 |
| 策略库 | `/strategies` | 管理我的策略、内置策略、导入/导出、版本与策略复用 |
| 回测研究 | `/backtests` | 创建/配置回测、选择股票池与策略、提交回测任务、查看回测分析入口 |
| 成果库 | `/artifacts` | 按选股成果/回测成果浏览历史快照，查看来源任务、策略版本和结果详情 |
| 任务中心 | `/tasks` | 查看选股/回测任务、状态、进度、节点、取消/删除允许的任务 |
| 系统状态 | `/system` | 展示 Node1/2/3、队列、运行健康与诊断信息；不混入用户成果 |

账户菜单：个人信息/退出登录。管理员功能继续放在独立的 `/admin`，不作为普通用户一级导航。登录、注册继续使用 `/login`、`/register`。

## 4. 核心页面职责边界

### 选股工作台
- 默认登录入口，优先优化公式编辑、策略选择、执行与结果预览。
- 仅展示当前执行的必要状态；完整历史结果进入成果库，所有任务进入任务中心。
- 不把策略库、自选股管理、回测报告和集群监控继续堆在同一页面。

### 股票研究
- 以股票为中心呈现 K 线和研究信息。
- 股票详情是跨流程的连接页：可加入自选股、从当前股票启动研究；不把股票本身当成策略或成果。

### 策略库
- 选股策略与回测策略属于统一策略域，但类型明确、独立保存。
- 回测策略可引用选股策略；提取功能生成新的选股策略对象，不覆盖原回测策略。
- 编辑必须产生新版本或可追踪版本记录；历史任务绑定其实际使用的策略版本。

### 自选股
- 一个用户可拥有多个自选股列表；列表是可维护的股票集合，不是策略。
- 列表成员变更不修改已提交任务或历史成果中的股票池快照。

### 任务中心与成果库
- 任务中心回答“运行发生了什么”；成果库回答“历史计算产出了什么”。
- 任务状态/进度可以变化；成功成果的内容与元数据快照不可因策略、自选股或模板后续修改而变化。
- 成果详情应追踪到来源任务、策略 ID/版本、参数快照、数据/日期范围及 Artifact 引用。

### 系统状态
- 只展示平台运行能力：节点健康、队列、运行任务与诊断。
- 不将系统状态建模为用户成果，也不允许前端绕过 Scheduler 直接控制节点计算。

## 5. 重要对象的页面映射

| 对象 | 主入口 | 详情/关联 |
|---|---|---|
| 选股策略 | 策略库 | 策略详情、版本、选股工作台 |
| 回测策略 | 策略库/回测研究 | 策略详情、版本、回测配置 |
| 自选股列表 | 自选股 | 列表详情、股票详情、回测股票池选择器 |
| 股票 | 股票研究 | 选股结果、成果详情、自选股列表 |
| 任务 | 任务中心 | 任务详情、成果详情 |
| 选股成果 | 成果库 → 选股成果 | 结果表、股票详情、加入自选股 |
| 回测成果 | 成果库 → 回测成果 | 指标、交易/持仓明细、来源策略版本 |
| Artifact | 成果详情内部 | 大型结果数据的持久化引用，不作为一级导航 |

## 6. 关键交互流

1. **选股：** 选股工作台 → 选择/编辑策略 → 提交选股任务 → 任务中心跟踪 → 生成选股成果 → 股票详情/加入自选股。
2. **策略研究：** 策略库选择回测策略 → 回测配置（策略 + 股票池 + 参数）→ 提交任务 → 任务中心 → 回测成果详情。
3. **复用选股策略：** 回测策略引用选股策略版本；或从回测策略提取生成独立选股策略，不反向修改回测策略。
4. **自选股回测：** 自选股列表 → “用作回测股票池” → 回测配置中保存本次股票池快照 → 任务执行。
5. **历史追踪：** 成果详情 → 来源任务 → 实际策略版本与参数快照 → Artifact。

## 7. URL 与兼容策略

- 上表是目标 URL，不代表这些路由当前都已实现。
- 当前 `/` 是聚合式工作台，先保留为兼容入口；首个迁移阶段让 `/` 与 `/select` 共用选股工作台实现，验证稳定后再决定是否将 `/` 重定向到 `/select`。
- 对现有登录、注册、管理员路由保持兼容。
- 若当前应用存在查询参数或旧链接，迁移时保留可访问性；旧页面状态不得在路由拆分后丢失。
- 详情页使用稳定 ID（`strategyId`、`watchlistId`、`taskId`、`artifactId`）；股票代码使用 `symbol`。URL 不使用列表名称、公式文本或结果内容作为标识。
- 需要避免歧义：策略 ID 唯一，类型通过策略记录字段确定；URL 可按类型分段以提升可读性。

## 8. 渐进式重构顺序

### IA-0：锁定基线
- 保存本文档，确认目标页面树与对象职责。
- 梳理现有 `page.tsx` 中的区块、状态、API 请求和事件处理，形成迁移清单。
- 暂不改计算内核、任务调度和现有 API 合约。

### IA-1：建立应用壳与选股路由
- 提取登录态/全局布局/主导航。
- 新增 `/select`，先复用现有选股核心逻辑。
- 保证 `/` 旧入口仍可用，回归登录与选股 E2E。

### IA-2：拆出独立页面
- 依次拆出股票详情、自选股、策略库、回测研究。
- 优先提取页面容器和业务 hooks，不先做大规模视觉改版。

### IA-3：任务与成果分离
- 建立任务中心和成果库独立路由。
- 确保历史成果绑定任务输入快照及策略版本。
- 系统状态独立成页。

### IA-4：验证与清理
- 路由直接访问、刷新、返回导航、权限隔离和移动端回归。
- 验证选股仍为默认工作流，选股优先/回测可被抢占等调度行为未改变。
- 所有关键页面通过 E2E 后，再删除旧聚合页中的重复实现。

## 9. 本阶段验收标准

- 页面树、导航、URL、对象职责在文档中明确。
- 每个一级导航有单一清晰职责；任务与成果不再混为一体。
- `/` 仍可用，登录后默认进入选股工作流。
- 尚未实现的目标路由明确标注，不假定后端 API 或持久化能力已经存在。
- 本阶段只建立 IA 基线；代码拆分和路由实施作为后续独立阶段。
